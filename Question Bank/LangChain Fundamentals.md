| **No.** | **Question**                                                                           | **Answer**                                                                                                                                                                                                                                          |
| ------: | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
|   **1** | What is LangChain and what is its primary purpose?                                     | LangChain is an open-source framework for building production LLM applications. It connects language models, prompts, retrieval (vector stores/indices), memory, chains, and agents to build chatbots, RAG systems, and tool-using AI applications. |
|   **2** | How is LangChain different from directly using an LLM API like OpenAI?                 | LangChain provides higher-level building blocks such as chains, prompt templates, memory, vector store integrations, agents, tools, orchestration, and monitoring, making complex workflows easier to build.                                        |
|   **3** | What is Memory in LangChain, and how does it manage multi-turn conversations?          | Memory stores conversation history and facts across interactions. Memory modules replay relevant history into prompts so applications maintain context during conversations.                                                                        |
|   **4** | What are Tools in LangChain and how do agents use them?                                | Tools are functions or APIs that agents can call (search, calculator, database queries, etc.). Agents choose tools based on their descriptions during reasoning.                                                                                    |
|   **5** | What is a Chain in LangChain and how does it work?                                     | A Chain is a sequence of components (prompts, LLM calls, retrieval, post-processing) where the output of one step becomes the input to the next.                                                                                                    |
|   **6** | What is Retrieval-Augmented Generation (RAG) and how does LangChain support it?        | RAG combines retrieved documents with LLMs by embedding documents into a vector store, retrieving relevant content, and providing it to the LLM for factual responses.                                                                              |
|   **7** | What is a Vector Store or Index in LangChain, and when would you use one?              | A Vector Store stores embeddings and performs semantic similarity searches. It is used for RAG, document search, recommendation systems, and semantic retrieval.                                                                                    |
|   **8** | When should you use a Chain vs when should you use an Agent?                           | Use a Chain for fixed, deterministic workflows. Use an Agent when dynamic reasoning, tool selection, and multi-step decision-making are required.                                                                                                   |
|   **9** | What are the key principles of Prompt Engineering when building LangChain apps?        | Keep prompts explicit, structured, use templates, provide relevant context, test edge cases, and implement guardrails for safety.                                                                                                                   |
|  **10** | How do memory modules work in LangChain for multi-turn conversations?                  | Memory components store previous messages and insert them into prompts using keys like history. Different memory strategies optimize token usage and relevance.                                                                                     |
|  **11** | How does LangChain handle long documents (multi-page or large PDFs)?                   | Split documents into chunks, embed them, store them in a vector database, retrieve relevant chunks, and optionally summarize them before answering.                                                                                                 |
|  **12** | How can you handle API rate limits and costs efficiently in LangChain applications?    | Use caching, local embeddings, hybrid retrieval, smaller models for filtering, queue/backoff strategies, and monitor token usage and costs.                                                                                                         |
|  **13** | What are the best ways to debug and monitor LangChain applications?                    | Use structured logging, record prompts and responses, trace with LangSmith, monitor latency, token usage, correctness, and create unit tests.                                                                                                       |
|  **14** | What factors must be considered when deploying a LangChain app to production?          | Consider scalability, latency, cost, security, API key management, vector database availability, monitoring, and privacy compliance.                                                                                                                |
|  **15** | How can LangChain be used to build multi-modal workflows (text + image + audio)?       | Use multimodal embedding models or separate OCR/speech-to-text pipelines, embed each modality, store metadata, and combine retrieval results.                                                                                                       |
|  **16** | How do you design evaluation metrics for LangChain apps?                               | Measure correctness, retrieval precision/recall, latency (P95), token cost, and user satisfaction, then tie them to alerts and SLAs.                                                                                                                |
|  **17** | How do you integrate LangChain with existing databases (SQL, NoSQL, Knowledge Graphs)? | Index data into vector stores, create database query tools, validate outputs, and feed retrieved results into chains.                                                                                                                               |
|  **18** | How would you design a hybrid RAG + Agent workflow?                                    | Combine a RAG chain for contextual retrieval with an agent that dynamically decides when to call APIs or tools.                                                                                                                                     |
|  **19** | Explain the architecture of LangChain.                                                 | Major components include the LLM layer, Prompt Templates, Retrieval (Embeddings + Vector DB), Memory, Chains, Agents, and Tools working together to build AI applications.                                                                          |
|  **20** | How can you optimize a LangChain pipeline to reduce LLM costs without losing accuracy? | Use response caching, prompt compression, and selective retrieval to minimize unnecessary LLM calls.                                                                                                                                                |
|  **21** | Why use LangChain instead of directly calling an LLM API?                              | LangChain provides reusable components like Chains, Agents, Memory, Tools, and Vector Stores, making applications modular and production-ready.                                                                                                     |
|  **22** | What is Memory in LangChain?                                                           | Memory stores previous messages and conversation history, enabling multi-turn, stateful conversations.                                                                                                                                              |
|  **23** | What is Prompt Engineering in LangChain?                                               | Designing structured, context-rich prompts with placeholders to guide LLM responses consistently and safely.                                                                                                                                        |
|  **24** | How do you secure LangChain applications?                                              | Use tool whitelisting, sanitize inputs, prevent prompt injection, restrict file/OS access, store API keys securely, and log anonymized data.                                                                                                        |
|  **25** | What caching strategies can reduce LangChain costs?                                    | Use in-memory caching, Redis/GPTCache, embedding caching, and prompt compression through summarization.                                                                                                                                             |
|  **26** | How can you store and reuse conversational context in LangChain?                       | Use Memory modules such as ConversationBufferMemory, ConversationSummaryMemory, and ConversationBufferWindowMemory.                                                                                                                                 |
|  **27** | How can LangChain be deployed as an API or web app?                                    | Wrap LangChain workflows using FastAPI, Flask, or Streamlit for deployment.                                                                                                                                                                         |
|  **28** | What is a RAG pipeline in LangChain?                                                   | Load → Split → Embed → Store in Vector DB → Retrieve → Generate responses with the LLM using retrieved context.                                                                                                                                     |
|  **29** | What is LCEL in LangChain?                                                             | LCEL (LangChain Expression Language) is the Runnable-based functional pipeline system supporting streaming, asynchronous execution, and parallel workflows.                                                                                         |
|  **30** | What is a multi-step reasoning chain and how do you build one?                         | Break reasoning into steps such as Decompose → Retrieve → Generate → Validate using sequential Runnables or Plan-and-Execute agents.                                                                                                                |

|  **41** | How would you handle API errors or timeouts in LangChain?                                            | Wrap API calls in try/except blocks, implement exponential backoff retries, log failures, apply fallback logic, and continue the workflow safely.                     |

|  **43** | How would you handle multiple users chatting with the same application?                              | Assign unique session IDs, maintain separate memory for each user, store chat history in a database, and dynamically load memory for each session.                    |

|  **57** | How can you run different workflows based on output conditions?                                      | Evaluate the model output, check condition flags, execute Chain A or Chain B accordingly, merge results, and return the final response.                               |
|  **58** | How do you refine an answer until it meets a quality standard?                                       | Generate an answer, evaluate it using an evaluator chain, refine the prompt if necessary, repeat until the quality threshold is reached, and return the final answer. |
|  **59** | How do you connect LangChain to external APIs or databases?                                          | Define API functions, wrap them as Tools, register them with AgentExecutor, allow the LLM to invoke them, and return the results.                                     |
|  **60** | How do you manage multiple users running LangChain workflows simultaneously?                         | Assign unique user sessions, execute asynchronous chains or job queues, isolate memory for each user, scale horizontally, and monitor resource utilization.           |
